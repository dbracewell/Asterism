## Environment and boundaries

Frozen pnpm installation passed offline from local caches; `uv sync --locked
--offline` resolved 149 packages and checked 127 installed packages. Dependencies
were not changed or purged. This verifies pinned installation with the existing
cache/environment; it does not claim a new operating-system or empty-cache install.

Each isolated browser run creates fresh model-driven backend SQLite, Better Auth,
source, extraction/vector storage, and synthetic credentials. Both applications use
the runner's unique paths. A loopback-only bridge supplies the backend's fixed
internal frontend topology while Next.js remains on its separate test port. Occupied
ports are not replaced. No working database was reset and no provider model bundle
was downloaded. A fresh-install Playwright project precedes account-creating tests.

unit tests cover installation and rendering, and final browser logs contain zero unredacted token query values. Earlier failed-run
diagnostic logs were also scrubbed of obsolete synthetic query credentials.

## Scope resolution measurements

`test_scope_query_bounds.py` creates project members, unrelated same-owner library
files, and foreign-owner sources, then measures the production scope reader. The
reported set must equal only the owned project members.

| Project members | Total library sources | SQL SELECTs | Observed scope time |
| --------------: | --------------------: | ----------: | ------------------: |
|              10 |                    30 |           6 |            3.170 ms |
|             100 |                   300 |           6 |            2.913 ms |
|           1,000 |                 3,000 |           6 |            5.760 ms |

These are local temporary-SQLite observations, not latency guarantees. Six selects
cover chat identity, branch messages, local sources, project identity, project
sources, and selected targets; the test asserts no per-file query growth. Returned
file/provenance memory and sorting grow with allowed files, and branch reading grows
with stored chat messages. This is not a long-history/concurrent production load
test. Retrieval separately enforces its configurable allowed-file limit (default
1,000), result-count limit, and excerpt-byte budget. Tests cover over-limit rejection.

Measurements were recorded with `-o junit_family=legacy --junitxml=...`, avoiding
pytest's xunit2 property warning from the first metrics run. Wall times are recorded
but not used as brittle assertions.

## Initial failures and repaired verification

The initial full browser run had one cold attachment-panel flake and a new fixture
using the wrong project-selection method. Subsequent focused runs corrected fixture
method, file-input locator, settings deep link, and attachment expectations. The
panel test now waits for a controlled open state and repeats an opening action only
while closed, instead of depending on a click before hydration. No product behavior
was changed to satisfy those fixture assumptions.

Focused security tests initially compared create-response branch metadata to a
read response; the final regression compares canonical reads before/after denied
access. Those failed runs and the first xunit2 warnings are not counted as passes.
The final browser run uses `--retries=0`; it cannot conceal a flaky result via retry.

## Reproduction and final receipts

Run from the repository root with dependencies installed. Local runs used
`UV_CACHE_DIR=/private/tmp/asterism-uv-cache` and disabled pnpm's automatic
before-run dependency reinstall; neither changes application behavior.

```bash
pnpm install --frozen-lockfile --offline --config.strictDepBuilds=false --config.ignore-scripts=false
uv sync --directory apps/backend --locked --offline
pnpm format
pnpm lint
pnpm typecheck
pnpm check:workspace-tasks
pnpm test
pnpm build
CI=1 node scripts/run-isolated-e2e.mjs --retries=0
pnpm --filter @asterism/backend cycles
```

The final full isolated suite ran after the isolated-only marker and explicit
fresh-install dependency were added. It passed all 27 tests without retries or
skips; the runner exited 0. The backend's exit 143 is its intentional SIGTERM
teardown. Expected Node deprecation/color notices and draft-title fallback warnings
are not unhandled browser errors. Full earlier/focused failures are not substituted
for this receipt. No remote CI jobs or live-provider tests are claimed.

The occupied-port negative check bound a controlled server on port 3000, ran the
isolated launcher, and verified refusal (`EADDRINUSE`), the existing server still
responding, and an empty temporary runner directory afterward. It passed. Direct
Playwright does not run the mutating authenticated scenario unless the isolated
runner's explicit marker is present.

Independent client generation used the isolated server's served OpenAPI, generated
into a separate temporary directory, formatted there, and compared all client files
with the checked-in tree. The final server schema was identical to that input.
No generated client or public schema change was needed.
