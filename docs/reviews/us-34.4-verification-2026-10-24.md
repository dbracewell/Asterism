## Implemented behavior

Admission atomically checks global and authenticated-owner counts on the
single-process asyncio event loop. Defaults are 32 chat-work slots/four per owner
and 128 controllers/16 per owner. Configuration rejects zero, excessive global
values and per-owner values exceeding the global limit.

Controller reservations precede history reads, Agent construction and controller
queues/tasks. Failed setup releases reservations. Work admission precedes task
creation and closes rejected generation coroutines. Saturation returns an error
packet with code 503, `error_code: "chat_capacity"` and `retryable: true`.
Controller saturation closes with 1013; work saturation preserves the control
channel and never adds a capacity waiting task.

One chat-work slot covers generation, title tasks and approval waits, including
provider semaphore waits. Disconnect releases only the controller; reconnect
reuses active work. Completion/failure/cancellation release work after all parts
finish. Deletion/shutdown cancel and await tasks and cancel leftover approval
futures. Shutdown rejects admission and releases controllers; release is
idempotent. Owner mismatch cannot reuse another owner's runtime/admission.

No HTTP/schema/client-generation or database schema change was needed. No
migration or working database reset was performed. Knowledge queue admission,
byte bounds, distributed coordination and general load certification remain
outside this story; existing model/knowledge execution gates are documented
separately.
