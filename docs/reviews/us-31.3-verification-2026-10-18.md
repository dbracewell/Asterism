# US-31.3 verification — 2026-10-18

Implemented and verified on `feat/us-31.3-markdown-trust-boundary`. The user
confirmed completion on 2026-10-18 and authorized commit and local merge, accepting
the clarified omitted-image policy. EPIC-31 is confirmed complete.

## Result

- The shared main/user/sub-agent Markdown renderer disables raw HTML using
  `skipHtml`; `rehype-raw` was removed from the source, dependency manifest and
  lockfile along with its unused transitive dependencies. No replacement raw-HTML
  path or sanitizer compatibility mode was added.
- One renderer-owned URL transform permits anchor links only: explicit HTTP(S)
  without credentials, single-slash application paths and document fragments.
  Script/data/blob/file/mailto/FTP schemes, protocol-relative URLs, backslashes,
  whitespace/controls and other relative URLs are not clickable. Anchors do not
  prefetch and use `noreferrer noopener`.
- Markdown images render omitted-image text with their alt text. They create no
  image elements or automatic resource URLs, including authenticated same-origin
  endpoints. Existing authorized attachment previews remain separate components.
- KaTeX uses trust disabled, strict validation and explicit expansion/size limits.
  User HTML/style/ID/class, link and image commands cannot install active markup.
  Trusted math layout output remains usable, including inline/display/fenced math.
- Fenced code remains literal, highlighted and copyable; GFM tables, disabled task
  lists, footnotes and scoped-file references remain available. Structured
  retrieval citations retain their existing live metadata/authorization boundary.
- File extraction/captions remain plain React text rather than another HTML or
  Markdown renderer. Added adversarial coverage preserves that contract.
- The [content policy](../architecture/markdown-content.md) records approved
  content, link/resource rules, pipeline ownership, math settings and the remaining
  US-32.3 layout scope. Affected READMEs/security guides and planning status are
  updated. No backend schema/OpenAPI or Hey client contract changed.

Commands used the existing installed dependencies with
`--config.verifyDepsBeforeRun=false`, or
`pnpm_config_verify_deps_before_run=false` for nested Playwright commands. No new
runtime dependency was introduced. The dependency removal was synchronized with
`pnpm install --lockfile-only --offline --ignore-scripts`. The resulting temporary
local pnpm store was removed; manifests and lockfile retain the intended removal.

The 34 focused renderer cases exercise overlays, raw forms/frames/scripts/media,
resource attributes, remote/same-origin/data/blob images, unsafe and encoded URLs,
credential-bearing URLs, trusted versus untrusted math, bounded math
size/expansion, streamed fragments, code copying, GFM and footnotes. The file-view
regression checks literal extraction/caption payloads. Existing full-suite tests
also retain citation revocation and scoped attachment behavior.

The browser harness uses the shared renderer for the main-reply surface and the
actual sub-agent panel, retrieval citation component and FileView. Metadata,
extraction and token responses are synthetic/mocked; this is a rendering/network
boundary check, not a new real-auth chat integration test. All adversarial resource
URLs are intercepted before navigation, so a regression would be recorded without
contacting an external host. The run verified zero such requests, no executable
marker/page errors, inert file content, usable math, link policy, source paths and
actual clipboard copying. Both the initial browser run and the final run passed
without retries. The first unit run had one overly specific token-class assertion;
it was corrected to verify the highlighter's rendered colored spans, and subsequent
focused and full suites passed. Routine Node deprecation notices remain in output.

The full browser suite, backend quality gates, combined-container build/deployment
and remote CI were not run for this frontend-only story. No working database reset,
deployment or push is claimed. Rich-content wrapping and composer
clearance remain US-32.3 and were not silently folded into this change.
