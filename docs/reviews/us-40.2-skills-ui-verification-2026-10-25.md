## Delivered behavior

- User Settings → Skills (`/settings?t=user&setting=skills`) provides generated
  query-backed search/pagination, create from a SKILL.md template, detail view,
  source editing, safe Markdown preview, and revision-checked confirmed deletion.
- Preview uses the existing shared Markdown renderer: raw HTML is skipped,
  unsafe links are removed, and remote images are omitted. No additional UI
  library/dependency was installed. Server validation remains authoritative;
  the editor counts UTF-8 bytes and blocks oversized saves.
- Initial failure/retry, empty results, and cached-refresh failure remain
  distinct. Mutation/refresh failures retain source and original revision.
  Explicit reload confirms discarding dirty drafts. Pristine editors adopt newer
  detail data, and save/delete wait for detail refresh. Closing dirty source
  asks before discarding. Deletion restores focus to New skill; deleting the
  last item of a later page returns to a valid page.
- Agents → Manage main-agent skills is a separate dialog, with a bottom-right
  Save assignments action. It preserves selections across pages/search and
  submits only skill IDs plus the captured main configuration revision. It never
  writes instructions, tools, generation defaults, or admin policy.
- Policy status uses the authenticated eligible-discovery API. Editing and
  assigning remain available when policy is disabled; UI copy explicitly notes
  that runtime activation is still planned. No admin policy editor is added.
- Private query keys include the authenticated owner's identity while retaining
  generated prefixes for shared mutation invalidation. Owner changes clear open
  drafts; assignment owner scope comes from user context, not cached main-agent
  data. Components do not duplicate query invalidation.
- Existing settings navigation preserves unrelated/repeated URL parameters.
  Updated all READMEs, AGENTS.md, architecture docs, epic and checklist status.

The first browser run had 19 passes and three failed CRUD cases. It exposed a
real detail-cache race: reopening after save could pin an older revision for
subsequent deletion. The editor now adopts fresh data only while pristine and
blocks destructive actions during refresh, preserving unsaved text. The tests
also wait for asynchronous dialog close/deletion rather than mistaking modal
background hiding for row removal. Subsequent complete selected browser runs
passed; the final run includes authenticated-owner cache/draft isolation.

The four frontend failures are unchanged from the baseline documented in
