## Changes and audit

All five unfinished admin panes retain their existing Planned badges and
future-release explanations: Groups, Users, Image Generation, Code Execution and
Export. Their panes have no configuration actions or new API calls. The Code
Execution label is preserved.

Users now states that admin/user access checks already exist and that management
screens and permission-policy controls are planned. The audit checked
`user/dependencies.py`, `user/router.py`, `user/service.py`, Better Auth role
handling and the Settings page role gate. Backend listing, provisioning and
deletion are real lifecycle paths; this story adds no administration API.
Existing owner/admin authorization remains unchanged.

The root, backend and frontend READMEs and the
[product-surface guide](../architecture/frontend-and-themes.md#current-versus-planned-product-surface)
now separate available provider/model, agent, tool, theme and captioning settings
from the five planned panes. They distinguish image search/captioning from
generation, individual file downloads from bulk export, and provenance/typed
memory boundaries from future persona storage and long-term memory.

The desktop navigation rail leaves space for labels and badges. Long tab labels
wrap beside their badges, including long words, and focusing a
tab scrolls it fully into view. Horizontal tabs retain their natural width in a
scrolling row; vertical tabs can wrap within the navigation rail. This fixes clipped badges/text in vertical
navigation and partly hidden focused tabs in the horizontal scroller. The shared
URL utility and Radix keyboard behavior are retained.

The harness is public only under the test profile and cannot authorize APIs.
