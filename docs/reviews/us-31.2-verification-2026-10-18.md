# US-31.2 verification — 2026-10-18

Implemented and verified on `feat/us-31.2-durable-theme-storage`. The user confirmed
completion on 2026-10-18 and authorized commit and local merge. US-31.3 has not started.

## Result

- Read-only default palettes moved from `public/themes` to static imports in the
  theme domain. Custom palettes and bundled-ID overrides persist under the existing
  `STORAGE_ROOT/themes`, including the combined image's mounted `/storage` volume.
- A small `ThemeRepository` owns listing, reads and saves. Strict persisted JSON
  contains only `name`, `type` and `colors`; catalog IDs remain filename stems.
  No migrations, old-directory reader, generated client or schema/API migration
  was added. Backend OpenAPI and Hey API contracts are unchanged.
- Saves serialize duplicate-name checks within the supported single frontend
  writer process, await an exclusive temporary file/write/sync/close, and commit
  with a same-directory atomic rename. Failures preserve committed bytes and clean
  up temporary files. Symlink roots/targets and invalid IDs remain confined.
- Malformed custom files are isolated. Valid defaults survive invalid overrides;
  unavailable saved preferences resolve to Light without repeated refreshes.
- No palette cache is shared between requests/processes. Public responses declare
  `Cache-Control: no-store`; committed saves revalidate the root layout and refresh
  the editing browser. Other tabs update on navigation/refresh. Multiple concurrent
  writer processes on one volume are unsupported and documented.
- Save results are typed. Failed drafts remain editable with retry; successful
  creates install the returned server-generated ID so the next save updates that
  palette. Form controls/theme switching are disabled during a save. Shared
  TanStack mutation-cache invalidation is preserved without duplicate invalidation.
- Backup, permissions, reset retention and storage ownership are documented in
  [theme lifecycle](../architecture/theme-storage.md). Working storage was never
  reset or modified for verification.

`node scripts/check-theme-storage-container.mjs` transpiles the actual repository
and schema into a disposable test image on the local `asterism:local` runtime.

replacement, then read after another replacement. All run as UID/GID 10001 with a
read-only application filesystem and no network. The check verifies persisted bytes,
mode 0600 and immutable defaults, then removes its own image and volume. It does
not rebuild or run the entire combined application image. The new Docker utility
also requires its base image to be locally present rather than implicitly pulling it.
