## Delivered scope

- New `skills` domain and `skills`/`agent_skills` fresh-schema tables. Canonical
  SKILL.md-style source with bounded, scalar-only frontmatter validation;
  metadata is derived server-side and source round-trips unchanged.
- Owner-only create/read/search/page/update/delete APIs, 404 concealment for
  foreign/missing identities, database uniqueness/owner/role constraints,
  revision-checked edits/deletes, and atomic concurrent-write handling.
- Explicit main-agent skill assignments with the shared configuration revision,
  cross-owner and sub-agent denial, assignment cleanup/revision advancement on
  deletion, and user-deletion cascades. Unrelated main settings retain selections.
- Admin-only typed policy API, disabled by default, backed by strict-boolean
  `skills_enabled` validation on generic and bulk settings writes as well.
  Eligible discovery intersects ownership, assignment and live policy before
  pagination and returns metadata without document content.
- Updated model registry, architecture guard, generated Hey API types/SDK/query
  helpers/Zod schemas, AGENTS.md, all three READMEs, architecture docs, and
  [ADR-0022](../adr/0022-private-instruction-skill-foundation.md).
- PyYAML is now a direct dependency at the already-locked version 6.0.3; no other
  dependency version changed. YAML is scanned and composed as bounded scalar
  nodes; no arbitrary object construction, tags, aliases, anchors or nesting.

UI management, slash discovery, branch-active selections, prompt injection,
execution snapshots, and delegated skill activation remain later stories.
Enabling the policy here makes metadata eligible; it does not activate skills in
current chat execution or grant tools/files/MCP/delegation.
