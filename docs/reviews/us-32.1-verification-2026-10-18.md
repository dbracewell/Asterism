## Result

forms center using auto margins; taller forms remain scrollable from the first
field through submit. Scroll padding keeps keyboard focus clear of viewport
edges. The root body rules are unchanged. The mobile follow-up below gives the workspace
an explicit dynamic-height boundary and scroll ownership.

browsers, without disabling zoom. Setup and login use named forms and the existing
semantic `FieldError`: new and repeated failures focus the summary, preserve input
values and allow Tab navigation back through the fields. Long server messages
wrap, and the setup passkey label targets its own input.

The frontend README, root README, layout guide and planning/checklist documents
describe the implemented contract. The future US-33.2 label audit acknowledges the
passkey association repaired here. No backend, schema, generated API client,
dependency or auth persistence contract changed.

## Mobile workspace follow-up

The user reported that the sidebar would not open, the mobile header did not span
the screen, and pages did not scroll. This follow-up remains on US-32.1's feature
branch rather than starting another story before completion confirmation.

- Removed the trigger's `onTouchEnd` toggle; the synthesized click now activates it
  once for touch as well as mouse/keyboard.
- Replaced the overlapping negative-margin mobile header with a full-width sticky
  grid and 44px trigger. Page content has its own stacking context so chat widgets
  cannot cover the header; dialog portals remain above the workspace.
- Bounded the dashboard to `100dvh`, made its inset scroll ordinary pages, and gave
  the selected SettingsCard pane vertical scrolling. Desktop sidebar/resize widths
  do not shrink under page pressure. Project pagination wraps at narrow widths.
- The mobile drawer closes after route navigation and returns focus to its trigger
  on dismissal. Its close button has an accessible name, visible close icon and
  44px target. It omits the desktop expansion tooltip that previously consumed the
  first Escape. Navigation can scroll between the header and user footer.
- Two unit regressions check touch-end plus synthesized click, Escape/focus return
  and keyboard opening/navigation dismissal.

`mobile-shell.spec.ts` uses real authentication and production routes with
synthetic project/chat/file data and a mocked saved-chat socket. Ten cases cover
320/390px widths, 300px short pages and 600px chat/sidebar views: one-tap open,
Escape, close-button touch, keyboard reopen, actual route navigation, modal-lock
release, full-width header/hit testing, page and Settings scroll targets, Files
wheel scrolling and action hit testing, new-chat controls, and saved-history
scrolling in both directions with final-message/composer clearance. A short file
pane can show less than a whole card; its action is exposed by scrolling down and
slightly back up. Physical device gestures are not certified by these Chromium
wheel/touch checks.

The expanded browser run also exercises the existing real authenticated workspace,
agent settings, provider settings, saved-model chats, File Manager knowledge and
