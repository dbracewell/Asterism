## Delivered behavior

- Both new-chat and saved-chat General/project composers offer slash discovery
  from owned, assigned, policy-allowed metadata through generated TanStack queries.
- Leading exact commands preserve ordered unique selections. Picker selection
  resolves preceding commands in order. URLs, slash paths, inline code and later
  prose remain ordinary text. Unknown names and failed lookups retain the original
  message and require explicit literal-send opt-in.
- Active chips retain pinned revisions across follow-ups; remove, reorder and
  refresh controls stage changes for the next accepted message. Explicit selection
  of an updated active skill requests refresh. No automatic skill selection exists.
- Pending text/metadata/refreshes persist in versioned tab-local storage scoped by
  owner, workspace and source branch tip. Identity/branch changes cannot carry a
  pending selection to a different scope. Stale state retains drafts and offers
  confirmed reload. Unavailable skills can be removed before retrying.
- The input exposes combobox/list semantics with active-descendant keyboard
  navigation and scrolling. Escape closes; Shift+Enter/IME retain normal entry.
  Touch selection returns focus to the message. Skill-only sends are supported.
- Command resolution precedes attachment uploads; rejected sends retain text,
  skills and attachments. Request signatures include skill IDs/order/revision and
  refreshes. Existing sends read accepted state from the server before resuming.
  Historical messages display recorded skill names/revisions.
- Completion clears processing state even when a very fast turn misses an
  intermediate busy-status event. Welcome content now grows/scrolls safely in a
  320×300 viewport instead of centering overflow above the reachable area.
- Existing Popover/Button/Badge/FieldSet/Empty primitives are reused. No dependency,
  API schema, generated-client output or backend source changes were needed.

## Follow-up: admin activation control

The review identified the missing admin control for the default-disabled policy.
Added **Admin Settings → Skills** at `/settings?t=admin&setting=skills`, with
**Enable skill activation** and a bottom-right **Save skill policy** button.
The lazy pane guards non-admin rendering, uses generated GET/PUT policy clients,
and relies on shared global mutation invalidation to refresh policy, eligible
skills and chat state. Read failures offer retry without assuming a policy value;
denied/failed saves preserve the pending selection. The save writes only `{enabled}`.
Documents, assignments and historical snapshots remain unchanged when disabling.
