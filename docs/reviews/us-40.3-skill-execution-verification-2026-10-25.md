## Delivered behavior

- New/existing sends accept ordered revision-checked skill replacements, explicit
  refreshes and empty-set removal. Omission retains the active branch's pinned set.
- Canonical source is resolved server-side through owner/assignment/admin-policy
  checks. Failed validation leaves branch state, draft and receipt untouched.
  Skill selection is included in the idempotency fingerprint.
- Immutable accepted user-turn inputs preserve exact source, name and revision;
  execution metadata exposes identities/digests. One bounded `skills` prompt layer
  preserves explicit order after project instructions, without capability grants.
- Follow-ups, branch switching, source ancestry forks, replay and regeneration
  retain pinned inputs. New chats and delegates inherit no active skills.
- Live eligibility checks at execution and output/tool boundaries block revoked
  skills. Unavailable/update-available metadata permits removal or refresh; chat
  history remains readable and unavailable state does not invoke token estimation.
- Eight skills, 65,536 UTF-8 bytes per skill and 131,072 bytes aggregate are enforced
  before acceptance. Explicit nonempty selections support skill-only sends.
- Generated Hey API contracts and architecture/operator documentation are updated.
  Slash discovery, active composer chips/drafts and per-message display remain
  US-40.4; no new UI controls are claimed here.

## Commands and isolation

Backend checks ran from `apps/backend` with
`UV_CACHE_DIR=/private/tmp/asterism-uv-cache`:

```sh
node ../../scripts/run-with-env.mjs --env none --scope backend --profile test -- uv run pytest -q
uv run ruff check .
uv run basedpyright
uv run python -m compileall -q asterism
uv run ruff format --check .
uv run knot asterism
```

Frontend checks ran with `pnpm --filter @asterism/frontend` for `test`,
`test:migrations`, `typecheck`, `lint` and `codegen`. OpenAPI was exported from the
local app under the test environment to `/private/tmp`, then passed as
`OPENAPI_INPUT` to codegen. No live server or working database was required.

Database/API/runtime tests used disposable pytest storage. No migrations or
working-data resets were performed. Browser E2E and a production build were not
run for this backend/API story; frontend changes are generated client files only.
