## Delivered behavior

- Atomic initial persona creation, non-null owner-consistent default, bounded
  owner-scoped CRUD and revision conflicts. Database constraints protect defaults,
  selected-chat references, owner identity, size bounds and the 20-persona cap.
- Persona settings with retained drafts, explicit reload after conflicts, default
  switching, protected deletion, loading/error/retry states and owner-scoped caches.
- Chat selection follows the current default or a fixed persona. Accepted messages
  privately capture USER.md; immutable execution records preserve regeneration
  history. Public labels expose identity/revision, never private instructions.
- Resume retains recorded inputs. Regeneration explicitly captures current settings.
  Delegates inherit the root persona within existing model/tool/file ceilings.
  Live owner/profile checks revoke deleted personas before work and output release.
- No long-term memory store, automatic memory operations, migrations or legacy
  compatibility paths. Old development databases require an explicit fresh reset.
