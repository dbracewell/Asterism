Status: implemented and verified; awaiting completion confirmation on

## Implemented gate

- Every bundled JSON file is checked for registration, catalog ID and strict schema. All ten declared foreground roles are accounted for; every opaque text pair uses an unrounded 4.5:1 threshold. Reference, shorthand, invalid-color and near-threshold cases exercise the calculation. Current coverage: 8 palettes, 80 pairs, 96 new unit cases.
- The existing production-component fixture now includes named appearance controls, typography and adversarial content. Its layout follows the pane container rather than the outer viewport. The rendered contrast probe is shared with the new 24-case layout matrix (8 themes × 3 viewport/pane/text/motion configurations).
- The matrix checks document, pane and card overflow, ancestor clipping, center hit testing, named keyboard-focusable controls, selection and focus return, last-tab reachability, code/logo fonts, reduced motion and Markdown trust boundaries. JSON evidence is written even on failure; screenshots and traces supplement role/theme/configuration assertions.
- Actual layout repairs found by review: theme selectors shrink to their container, selected values permit truncation, and model-capability badges wrap. The fixture's implicit grid tracks now allow shrinking; its tab strip scrolls locally and long action labels wrap. The Montserrat wordmark remains unchanged.
- CI runs with zero retries and always retains HTML/JSON reports, screenshots and failure traces for seven days. Generated reports are gitignored. The [manual matrix and exception policy](../architecture/theme-layout-review-matrix.md) defines exact coverage and remaining checks.

## Diagnostics and limits

Initial diagnostics are not counted as passes. The first isolated startup timed
out before tests; checking the installed backend executable and a fresh run restored
startup. An anchored test-name filter selected no cases and was corrected. Initial
matrix assertions exposed scroll clearance and a legitimate GFM disabled checkbox;
the fixture now has scroll padding and preserves that documented renderer allowlist.
Stronger internal-panel checks then caught long-value/grid and capability-label
overflow at 200% text. Those layouts were repaired, with the worst-case Latte case
passing before the full gate. Failed diagnostic runs emitted JSON, screenshots and
trace ZIP paths without needing a retry. The first complete run passed all 24
new layout cases and all eight rendered contrast cases (118/119 overall); one
existing project-file assertion ambiguously matched description and status text.
It now targets the named `shared.txt` row and asserts that it is disabled and
contains the status. A second diagnostic run showed that an exact standalone text
locator was unsuitable for the combined row label. That run also encountered an
execution-context reload during a concurrent visual probe; its trace recorded Fast
Refresh rebuilding. The final run used no concurrent browser probes and passed all 119 cases.
The post-teardown typecheck caught a missing explicit type on the geometry evidence
array; adding that type changed no runtime behavior, and the repeated typecheck passed.

This is local verification, not a hosted GitHub Actions or Docker-job result. No
working database was reset. Browser storage/accounts and rendered content are
synthetic. Opaque text-pair coverage is complete for bundled themes; custom themes,
syntax token combinations, group opacity/gradients/overlap and physical-device
keyboard/screen-reader behavior still require the documented manual review. There
are no opaque paired-role threshold exceptions. The scoped assertions do not claim
whole-application WCAG conformance.
